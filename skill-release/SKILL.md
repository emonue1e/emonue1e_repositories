# Публикация скилла

Отвечай на языке пользователя.

## Что это за процесс

Скилл живёт в двух местах: исходник в git-репозитории и установленная копия в
claude.ai. Эти два места рассинхронизируются легко, а ошибки вылезают уже
после загрузки. Порядок ниже закрывает те грабли, на которые реально
наступали.

Скопируй чек-лист в ответ и отмечай:

```
- [ ] Шаг 1. Найден рабочий клон
- [ ] Шаг 2. Дубли проверены
- [ ] Шаг 3. Фронтматтер прошёл валидацию
- [ ] Шаг 4. Zip собран с папкой внутри
- [ ] Шаг 5. Запушено
- [ ] Шаг 6. Проверено через raw
- [ ] Шаг 7. Сказано про установку и замену
```

## Шаг 1. Найти рабочий клон

**Не клонировать заново, не проверив.** У пользователя может быть несколько
копий репозитория, и пуш из «не той» приводит к тому, что локальная папка
молча отстаёт.

```bash
find ~ -maxdepth 4 -name .git 2>/dev/null | sed 's|/.git$||' | while read d; do
  echo "$d → $(git -C "$d" remote get-url origin 2>/dev/null)"
done
```

Если клонов больше одного — показать список и спросить, какой рабочий.
Клонировать новый только если не нашлось ни одного.

## Шаг 2. Проверить дубли

Искать по смыслу, а не по имени. Похожее имя ничего не значит, и наоборот:
теория по теме и инструмент, который что-то измеряет, — разные скиллы, оба
имеют право на жизнь.

```bash
grep -ril "<ключевое слово темы>" --include=SKILL.md .
```

Отдельно проверить установленные скиллы: если такое имя уже занято, загрузка
в claude.ai не добавит новый скилл, а **заменит** существующий без
возможности отката.

## Шаг 3. Проверить фронтматтер

Обязательны `name` и `description`. Допустимы `version`, `license`,
`allowed-tools`, `compatibility`. Ограничения платформы, а не пожелания:

| Поле | Требование |
|---|---|
| `name` | до 64 символов, только строчные буквы, цифры и дефисы |
| `name` | не должно содержать слова `claude` и `anthropic` |
| `name` | обязано совпадать с именем папки |
| `description` | непустое, до 1024 символов, без XML-тегов |
| тело SKILL.md | до 500 строк, иначе выносить детали в отдельные файлы |

```bash
python3 - <<'PY'
import yaml,os,re
d='<папка скилла>'
t=open(f'{d}/SKILL.md').read()
fm=yaml.safe_load(t.split('---')[1])
n,desc=fm['name'],fm['description']
errs=[]
if n!=os.path.basename(d.rstrip('/')): errs.append('name не совпадает с именем папки')
if not re.fullmatch(r'[a-z0-9-]{1,64}',n): errs.append('name: только a-z, 0-9, дефис, до 64')
if re.search(r'claude|anthropic',n): errs.append('name содержит зарезервированное слово')
if not desc or len(desc)>1024: errs.append(f'description: {len(desc)} символов при лимите 1024')
if len(t.splitlines())>500: errs.append('SKILL.md длиннее 500 строк')
print('\n'.join(errs) if errs else 'валидация пройдена')
PY
```

Автоматика не ловит главное — смысл описания:

- **Третье лицо.** «Публикует скилл», а не «Я помогу опубликовать» и не «Вы
  можете». Описание попадает в системный промпт, смешение лиц ломает выбор.
- **Настоящие фразы-триггеры**, которыми скилл будут звать, а не абстрактная
  тема. Описание — единственное, что видно до загрузки скилла, по нему он
  выбирается среди сотни других.

## Шаг 4. Собрать zip

Внутри архива должна быть **папка**, а не файлы в корне. Это самая частая
ошибка сборки.

```bash
cd <родительская папка скилла>
zip -r <имя>.zip <имя>/ -x '*.DS_Store'
unzip -l <имя>.zip     # проверить: пути начинаются с <имя>/
```

## Шаг 5. Коммит и пуш

Свои скиллы кладутся отдельной папкой в корень репозитория. Никогда — внутрь
папок, которые являются зеркалами чужих проектов: при обновлении апстрима
правки потеряются.

```bash
git -C <клон> add <имя>
git -C <клон> status        # убедиться, что в индексе только нужное
git -C <клон> commit -m "Add <имя> skill: <в чём смысл>"
git -C <клон> push origin main
```

**Аутентификацию `git push` запрашивает сам.** Не проси у пользователя токен
или пароль и не принимай их, даже если предлагают.

## Шаг 6. Проверить результат

Проверять через raw, а не открывая страницу репозитория: raw-файл дешевле в
несколько раз по контексту, а подтверждает ровно то же.

```
https://raw.githubusercontent.com/<владелец>/<репозиторий>/main/<имя>/SKILL.md
```

## Шаг 7. Напомнить про установку

Это ручной шаг, автоматизировать его нельзя:

1. Settings → Capabilities → **Code execution and file creation**
2. Customize → Skills → загрузить zip
3. Проверить, что скилл включён тумблером — после загрузки он может остаться
   выключенным

**Если заменяется существующий скилл** — сначала сохранить копию старой
версии. Диалог «Upload and replace» предупреждает честно: восстановить нельзя.

## Шаг 8. Предупредить про «Unknown skill»

Сразу после загрузки слэш-команда может отдавать `Unknown skill`, хотя скилл
установлен корректно. Причина не в файле: список команд формируется при старте
сессии, а резолвер слэш-команд и загрузчик скиллов используют разные пути
поиска.

Порядок проверки: тумблер включён → перезагрузить страницу → открыть новый чат
→ позвать фразой-триггером. Если фразой работает, а слэшем нет — это баг
платформы, а не скилла.

## Чего не делать

- Не клонировать репозиторий заново, не поискав существующий клон.
- Не класть свои файлы в зеркала чужих репозиториев.
- Не принимать токены и пароли.
- Не заменять установленный скилл без резервной копии.
- Не проверять результат пуша через HTML-страницу репозитория, когда есть raw.
