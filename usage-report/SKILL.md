# Отчёт о расходе контекста

Отвечай на языке пользователя.

## Главное ограничение — не нарушать

Точная телеметрия (пик контекста, число обращений к модели, счётчик квоты)
изнутри разговора **недоступна** — это данные платформы. Не выдумывай их и не
пиши правдоподобных чисел. Считай измеримое, остальное помечай как оценку.

## Два разных понятия — не путать

| | Контекст (окно) | Квота (лимит использования) |
|---|---|---|
| Что это | рабочая память одного чата | сколько можно работать за период |
| Обнуляется | при старте нового чата | по расписанию плана |
| Признак упора | ранние сообщения сжимаются | сообщение о достижении лимита |

Ключевой механизм, который объясняет всё остальное: **вся история чата
отправляется модели заново на каждом ходу**. Поэтому расход квоты растёт
примерно квадратично от длины разговора. Скриншот, присланный на третьем
ходу, оплачивается снова на четвёртом, пятом и каждом следующем.

## Что считать точно

1. **Изображения** — пересчитай все в чате. Вес: 1.5–3K за крупный скриншот
   (полноэкранный, консоль), 0.5–1K за обрезанный кадр.
2. **Вызовы инструментов** — bash, view, create_file, web_search и прочие.
   Каждый = запрос + результат в контексте. `web_fetch` HTML-страниц дорог:
   5–15K за страницу.
3. **Файлы** — `stat -c%s <файл>`. Делить на ~3.2 байта на токен для кириллицы,
   ~4 для латиницы, ~3.5 для кода. Отметь, читан файл целиком или фрагментами.
4. **Обмены** — число пар «сообщение → ответ».

## Что оценивать

- Системная часть (инструкции, схемы инструментов, список скиллов): 25–35K.
  На пустом чате это почти всё заполнение — так и скажи.
- Собственные ответы: прикинь по числу и объёму.

## Размер окна

Не зашивай константу. Базовое окно 200K, на платных планах у новых моделей
бывает 500K и до 1M. Если реальный размер неизвестен — считай от 200K и
явно пометь допущение, либо дай вилку.

## Формат вывода

Сначала таблица статей расхода с колонкой «измерено / оценка». Затем блок:

```
Контекст:  XXX–XXXK из ~YYYK        [████████░░░░░░░░░░░░]  NN%
Обменов:   NN     Изображений: NN     Вызовов инструментов: NN
Прочитано за сессию суммарно: ~X,X млн токенов
```

Прогресс-бар — 20 ячеек. Заполнение считай по нижней границе вилки, чтобы не
пугать. Затем — вердикт одной строкой: продолжать, закругляться или пора
открывать новый чат.

Если в чате меньше 5 обменов и нет изображений — не рисуй дашборд,
скажи коротко, что мерить пока нечего.

## Разбивка по блокам работы

Если сессия длинная, добавь вторую таблицу: на что ушла квота по смысловым
блокам (тема A, тема B, оформление документа, обсуждение инструментов).
Это полезнее общей цифры — показывает, какая часть работы была дорогой.

## Рекомендации (только при высоком расходе)

- **Резать сессии по темам.** Три коротких чата дешевле одного тройной длины —
  из-за квадратичности. Но не дробить до микрочатов: системные ~30K платятся
  в каждом заново.
- **Обрезать скриншоты.** Полноэкранный кадр с чёрным полем стоит втрое
  дороже кадра с нужными двадцатью строками.
- **Текстом вместо картинки**, когда вывод короткий. Картинка нужна там, где
  важен контекст окна: приглашение консоли, ошибка целиком, два окна рядом.
- **Крупные документы держать в проекте**, не вставлять в чат: подгружаются
  фрагментами по релевантности.
- **Tool access mode = «Load tools when needed»** в настройках: схемы
  инструментов не лежат в контексте постоянно.
- **Закрывать чат на логической границе**, а не когда упрётся.

## Чего не делать

- Не изобретать недоступные числа и не называть оценку измерением.
- Не тратить на отчёт больше, чем он экономит: таблица и бар, не графики.
- Не советовать экономию в ущерб делу: один уточняющий скриншот дешевле
  трёх ходов угадывания.
