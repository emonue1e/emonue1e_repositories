# Сверка справочника по скиллам

Отвечай на языке пользователя.

## Задача

Справочник по скиллам устаревает молча: плагины обновляются, скиллы
добавляются, документ остаётся прежним. Этот скилл сравнивает документ с
фактическим списком и дописывает разницу, не ломая оформление.

Скопируй чек-лист в ответ и отмечай:

```
- [ ] Шаг 1. Фактический список собран
- [ ] Шаг 2. Справочник прочитан
- [ ] Шаг 3. Структура документа определена
- [ ] Шаг 4. Разложено по категориям
- [ ] Шаг 5. Поля заполнены
- [ ] Шаг 6. Результат проверен
```

## Шаг 1. Собрать фактический список

Источник истины — список доступных скиллов текущей сессии. Он уже в контексте,
искать в интернете нечего.

Если нужен список файлов на диске:

```bash
ls ~/.claude/skills/ 2>/dev/null
find ~ -name SKILL.md -maxdepth 6 2>/dev/null | head -50
```

Имена скиллов с приставками (`anthropic-skills:`, `engineering:`,
`productivity:`) в документе принято писать без приставки в заголовке, а саму
приставку указывать в поле «Как запустить».

## Шаг 2. Прочитать справочник

Для `.docx` — извлечь текст, не ломая файл:

```bash
python3 -c "
import zipfile,re,html
x=zipfile.ZipFile('<файл>.docx').read('word/document.xml').decode('utf-8')
x=re.sub(r'</w:p>','\n',x); x=re.sub(r'<[^>]+>','',x)
print(html.unescape(x))
"
```

Собрать список уже описанных скиллов и сравнить множества в обе стороны:

- есть в системе, нет в документе → дописать;
- есть в документе, нет в системе → плагин удалён или переименован, спросить
  пользователя, убирать ли раздел. Молча не удалять.

## Шаг 3. Определить структуру документа

**До первой распаковки** выполнить раздел «Обязательно» ниже: резервная копия
и проверка, что документ не открыт в Word. Дальше файл трогать уже поздно.

Прежде чем писать, выяснить, каким разметочным шаблоном оформлены
существующие записи, и повторить его буквально. Для `.docx`:

```bash
unzip -q <файл>.docx -d unpacked/
find unpacked -type l -delete
grep -o 'w:pStyle w:val="[^"]*"' unpacked/word/document.xml | sort | uniq -c
```

Взять один готовый блок скилла целиком как образец и генерировать новые по
нему. Не изобретать свои стили и не переформатировать документ.

Если текст в XML разорван на фрагменты и не находится поиском — сначала
склеить прогоны скриптом `merge_runs.py` из скилла docx. Word разбивает
видимую глазом фразу на десяток `<w:r>`, и без склейки якорь для вставки не
найдётся.

## Шаг 4. Разложить по категориям

Новый скилл идёт в существующую категорию по смыслу. Новую категорию заводить,
только если появилось три и больше скиллов, которым не находится места.

## Шаг 5. Заполнить поля

Держать тот же набор полей, что и в остальном документе. Типовой набор:

| Поле | Что писать |
|---|---|
| Для чего | что скилл делает, одним-двумя предложениями |
| Когда использовать | ситуация, в которой он нужен |
| Как использовать | реальная фраза, которой его зовут |
| Как запустить | точная слэш-команда с приставкой, если она есть |

Описания брать из фактических описаний скиллов, а не сочинять. Если у скилла
есть внешнее требование (подключённый MCP, переменные окружения, отдельное
подтверждение перед запуском) — писать это в поле «Как запустить».

## Шаг 6. Проверить результат

Собрать документ и проверить. **Не идти дальше, пока не пройдёт.**

```bash
(cd unpacked && zip -Xrq ../out.docx .)
python3 <путь к скиллу docx>/scripts/office/validate.py out.docx --original <оригинал>.docx
```

Ошибка → прочитать сообщение → поправить XML → повторить проверку.

Если скрипта валидации нет под рукой, минимум: файл открывается как zip,
`document.xml` парсится, счётчик заголовков вырос ровно на число дописанных
записей и ничего не пропало.

Затем отрендерить одну страницу с новым разделом и посмотреть глазами,
совпало ли оформление с остальным документом:

```bash
soffice --headless --convert-to pdf out.docx
pdftoppm -jpeg -r 80 out.pdf page
```

## Обязательно

- **Сделать резервную копию документа перед правкой.** Если документ не под
  git, откатить будет нечем.

  ```bash
  cp <файл>.docx <файл>_backup_$(date +%F).docx
  ```

- Проверить, что документ не открыт в Word: файл-замок вида `~$имя.docx` в той
  же папке означает, что правки могут быть затёрты при сохранении из Word.

  ```bash
  ls <папка>/~\$* 2>/dev/null && echo "ВНИМАНИЕ: документ открыт в Word"
  ```

## Чего не делать

- Не переписывать существующие описания без просьбы — задача в том, чтобы
  дописать недостающее.
- Не менять формат документа по своей инициативе.
- Не выдумывать описания скиллов, которых не видел.
- Не сохранять поверх открытого в Word файла.
