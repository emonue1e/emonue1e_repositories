# Опрос перед началом работы

Отвечай на языке пользователя.

## Зачем

Дорогие ошибки случаются не от незнания команд, а от неспросённого. Второй
клон вместо существующего, правка не того файла, коммит в зеркало чужого
репозитория — всё это стоит времени и лечится пятью вопросами в начале.

Задача: собрать картину, зафиксировать её в `CLAUDE.md` проекта и дальше
работать по ней, не переспрашивая.

```
- [ ] 1. Осмотреться самому
- [ ] 2. Задать только недостающее
- [ ] 3. Показать понимание на подтверждение
- [ ] 4. Записать в CLAUDE.md
```

## Шаг 1. Осмотреться самому

**Не спрашивать то, что видно.** Сначала собрать факты, потом задавать вопросы
только о том, что из файлов не следует.

Это главный режим отказа таких опросников: имея на руках подробный контекст
проекта, они всё равно задают общие вопросы. Пользователь отвечает то, что уже
написано в README, и справедливо раздражается.

```bash
find ~ -maxdepth 4 -name .git 2>/dev/null | sed 's|/.git$||' | while read d; do
  echo "$d → $(git -C "$d" remote get-url origin 2>/dev/null)"
done
```

В самом проекте посмотреть: `CLAUDE.md`, `README.md`, `CONTRIBUTING.md`,
`.gitignore`, структуру корня, ветку по умолчанию, последние коммиты, файлы
менеджера пакетов для стека и версий.

Отметить для себя:

- сколько копий репозитория и совпадают ли их remote;
- какие папки в корне — свои, а какие зеркала чужих проектов (по вложенному
  `.git`, по `LICENSE` с чужим правообладателем, по README апстрима);
- стек и версии, команды сборки и тестов;
- на каком языке ведётся документация;
- в каких форматах документы: markdown, docx, смешанно.

## Шаг 2. Задать только недостающее

Спрашивать о том, чего не видно из файлов. Механизм — AskUserQuestion с
вариантами ответа: выбрать быстрее, чем печатать.

**Сколько вопросов за раз.** Простое и независимое — до четырёх пачкой.
Сложное, где следующий вопрос зависит от предыдущего ответа, — строго по
одному. Не вываливать весь список разом.

**Обязательный минимум:**

| Вопрос | Зачем |
|---|---|
| Какая копия репозитория рабочая | пуш из «не той» — самая частая тихая ошибка |
| Что нельзя трогать | зеркала чужих проектов, сгенерированные файлы, чужие ветки |
| Куда класть новое | корень, отдельная папка, определённая структура |
| Кто и как пушит | пушу я командой, пушите вы сами, только PR |

**Разделить обязательное и желательное.** Спросить прямо, что из названного
— требование, а что «хорошо бы». Без этого желательное съедает время,
отведённое на обязательное, а на вопрос «почему так долго» ответить нечем.

**Дальше — по обстоятельствам:**

- Нужно ли согласовывать перед разрушительными действиями: удалением,
  заменой файлов без истории, `git reset`, изменением чужих веток.
- Какие файлы существуют в одном экземпляре и не под git — их бэкапить перед
  любой правкой.
- Формат документов: если документ ведётся в Word, markdown ему не замена.
- Есть ли ограничения по стоимости работы: что считать дорогой операцией и
  когда спрашивать разрешения, а не делать.
- Язык ответов и язык коммитов — они могут различаться.

**Про доступы не спрашивать вообще.** Токены, пароли, ключи не запрашиваются
и не принимаются, даже если предлагают. Аутентификацию `git push` запрашивает
сам в терминале.

## Шаг 3. Показать понимание

**Это гейт, а не формальность. Не начинать работу, пока пользователь не
подтвердил.** Соблазн «уточню по ходу» здесь и приводит ко второму клону.

Изложить понятое коротким списком. Отдельно назвать то, в чём не уверен, —
правки обычно прилетают именно туда.

```
Понял так:
— рабочая копия: <путь>
— не трогаю: <список>
— новое кладу: <куда>
— пушите вы сами / пушу я
— обязательно: <список>   желательно: <список>
— перед <разрушительным действием> спрашиваю

Не уверен: <пункт>. Уточните?
```

Пользователь поправил — переспросить только по исправленному, не гонять весь
опрос заново.

## Шаг 4. Записать в CLAUDE.md

Договорённости, которые не записаны, забываются к следующей сессии.

Писать в `CLAUDE.md` в корне проекта: он подхватывается автоматически при
старте. Если файла нет — создать. Если есть — дописать раздел, не переписывая
чужое.

```markdown
## Стек

<языки, фреймворки, ключевые библиотеки — с версиями там, где они важны>

## Архитектура

<один абзац: монолит или сервисы, где что лежит, как части связаны>

## Команды

<сборка, тесты, линтер, локальный запуск>

## Правила работы

- Рабочая копия: <путь>. Других копий не заводить.
- Не трогать: <папки-зеркала, сгенерированное, чужие ветки>.
- Новое кладётся: <куда>.
- Пуш: <кто и как>.
- Перед удалением и заменой файлов вне git — резервная копия.
- <остальные договорённости>
```

Записывать только подтверждённое. Не додумывать правила за пользователя и не
превращать раздел в свод общих рекомендаций — там должно быть только
специфичное для этого проекта. Раздел «Не трогать» важнее остальных: он
единственный предотвращает необратимое.

## Когда опрос не нужен

- В `CLAUDE.md` уже есть раздел с правилами и он не противоречит задаче —
  прочитать и работать, ничего не переспрашивая.
- Задача на одно действие в файле, который пользователь сам назвал.
- Пользователь явно сказал не задавать вопросов — тогда действовать, но
  проговорить вслух сделанные допущения.

## Чего не делать

- Не задавать вопросы, ответы на которые видны в файлах.
- Не вываливать весь список вопросов разом.
- Не начинать работу до подтверждения понимания.
- Не смешивать обязательное с желательным.
- Не запрашивать токены и пароли.
- Не записывать в `CLAUDE.md` неподтверждённое.
